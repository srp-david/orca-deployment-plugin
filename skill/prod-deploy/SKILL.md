# prod-deploy — 운영 파일 반영

도구: `node "{{REPO}}/src/cli.ts"` (이하 `DEPLOY`). 단계·인자는 `{{REPO}}/src/cli.ts` 맨 위 설명에 있다. 대상 목록은 `DEPLOY targets`.

- 대상 설정: `~/.prod-deploy/targets/<대상>.json` (메인 체크아웃, FTP 주소·운영 루트, 경로 매핑, Java 빌드 출력, 손 처리 규칙). 고치는 것은 패널의 "대상 설정" 탭에서 한다.
- 접속 정보: Windows 자격 증명 관리자 `prod-deploy:<대상>`. 패널의 "접속 정보" 칸이나 `DEPLOY creds <대상> set`(stdin)으로 사람이 넣는다.
- run 기록: 대상 설정의 run 기록 폴더. 패널의 "run 기록" 탭에서도 본다.
- 용어는 `{{REPO}}/GLOSSARY.md`를 따른다(대상, run, 반영 목록, 확인 코드, 문제, 손 처리 파일, 매핑 밖 파일, 준비 확인 …).

이 스킬은 **파일만** 다룬다. SQL·톰캣 재기동·메뉴 등록·재로그인 확인은 사용자 몫이고, 순서는 PR 본문의 "반영 시 주의"를 따른다.

## 1. 준비 확인

1. 대상을 정한다. 사용자가 말한 대상, 아니면 `--target` 없이 지금 저장소로 찾는다. 시험용 대상은 사용자가 말할 때만 쓴다.
2. `DEPLOY check --target <대상> <PR|커밋|기준..끝>` — 병합됐는지, 메인 체크아웃이 main 이고 pull 됐는지, 바뀐 파일에 커밋 안 한 수정이 없는지, 바뀐 Java 가 main 소스로 빌드됐는지 본다.
3. 실패한 항목은 그대로 보여 주고, 나온 명령(pull·switch·빌드)은 **사용자가** 메인 체크아웃에서 실행하게 안내한다. 메인 체크아웃의 커밋 안 한 수정은 건드리지 않는다.

완료: 모든 항목이 통과했다.

## 2. 반영 목록 만들기 (운영 읽기만)

평소에는 사용자가 패널에서 PR 을 고르고 "반영 목록 만들기"를 누르면 된다(준비 확인 → plan → 백업). Claude 가 할 때:

`DEPLOY plan --target <대상> <PR|커밋|기준..끝> --backup` — 반영 목록을 만들고 운영 현재 파일과 대조해 확인 코드를 낸 뒤, 문제가 없으면 이어서 덮어쓸 운영 파일을 백업한다. "문제"가 나오면 멈추고 그대로 보여 준다(운영에만 있는 수정, 이미 반영됨, main 에 이후 변경 등). 백업만 다시 할 때는 `DEPLOY backup <run>`.

반영 시각이 정해져 있으면 반영 목록 만들기는 반영 직전에 한다(그 사이 운영 파일이 바뀌면 업로드 직전 대조에서 멈춘다).

"경고"(예: 상수 값이 바뀌었는데 그 이름이 나오는 소스가 반영 목록에 없음)는 업로드를 막지 않는다. 경고와 적힌 소스를 빼놓지 않고 그대로 보여 주고, 그 소스가 정말 그 상수를 쓰는지는 사용자가 판단하게 한다(쓰면 그 class 도 함께 올려야 한다). Claude 가 "문제없다"고 대신 판단하지 않는다.

## 3. 업로드는 패널에서 (기본)

반영 목록을 사용자에게 보여 주고(`DEPLOY show <run>`), **업로드는 Orca "운영 반영" 패널에서 사람이 누르도록** 안내한다: 반영 탭의 반영 목록(또는 run 기록 탭에서 그 run 더블클릭) → "<대상>에 N개 업로드". 올린 뒤 대조까지 자동으로 한다.
업로드 뒤 `DEPLOY show <run>` 으로 결과를 확인하고, 남은 사람 할 일(재기동·SQL·재로그인 확인·HISTORY.md 갱신)을 알린다.

### 패널을 못 쓸 때만: CLI 업로드

사용자가 "패널을 못 쓴다"고 말했을 때만 한다.

1. 반영 목록을 표로 보여 주고 AskUserQuestion 으로 묻는다("<대상> 운영에 이 N개를 올릴까요?").
   - 대상(이름·FTP 주소·운영 루트), 반영 커밋, run 이름, **확인 코드**
   - 올릴 파일마다 덮어씀/새 파일, 로컬 경로 → 운영 경로
   - 손 처리 파일과 이유, 매핑 밖 파일, class 가 있으면 "톰캣 재기동 필요"
2. 사용자가 이 목록을 보고 "올려"라고 답한 것만 승인으로 본다. 다시 plan 하면 새 목록으로 다시 묻는다.
3. `DEPLOY upload <run> --plan <확인 코드> --yes` — 훅이 확인 창을 한 번 더 띄운다. 거기서도 승인해야 실행된다. 올린 뒤 이어서 대조한다(대조만 다시 할 때는 `DEPLOY verify <run>`).

업로드가 중간에 멈추면(부분 업로드) 마지막 로그와 올린 수를 보여 주고, 되돌릴지 사용자에게 묻는다. 부분 업로드된 run 은 되돌리기만 할 수 있다.

## 되돌리기

패널의 run 카드 "되돌리기"를 안내한다. 패널을 못 쓸 때만, 반영 목록·백업을 다시 보여 주고 승인을 받은 뒤 `DEPLOY rollback <run> --plan <확인 코드> --yes`. 같은 파일을 건드린 나중 run 이 있으면 엔진이 막는다.

## 대상 추가

패널의 "대상 설정" 탭에서 "새 대상"으로 만든다(대상 이름에 `-` 는 쓰지 않는다). 접속 정보는 사용자가 직접 넣는다. 만든 뒤 "확인용 커밋"(이미 반영된 커밋)을 넣고 "설정 확인"으로 모든 파일이 "이미 반영됨"으로 나오는지 본다.

## 지킬 것

- 운영 FTP 쓰기는 `DEPLOY upload`·`rollback` 으로만 한다. 패널을 쓸 수 있으면 패널에서 사람이 누른다.
- 확인 코드는 사용자가 승인한 plan 의 것만 쓴다.
- 접속 정보와 netrc 파일은 열거나 출력하지 않는다. `DEPLOY creds ... set`·`unlock` 은 사용자가 요청할 때만.
