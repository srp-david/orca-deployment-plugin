# 운영 반영 엔진은 이 저장소의 TS 엔진 하나로 둔다

운영 반영은 처음에 개인 스킬(`~/.claude/skills/prod-deploy/`)의 bash `deploy.sh`로 만들었다. 그런데 Orca 패널과 Claude 스킬이 둘 다 같은 대상 설정, 판정 로직, 확인 코드 규칙을 써야 하고, 로직이 두 벌이 되면 대상을 잘못 고르거나 판정이 어긋나는 사고가 날 수 있다. 그래서 엔진을 이 저장소에 Node/TS로 다시 쓰고, 패널의 워커는 엔진을 직접 import하고 스킬은 이 저장소의 CLI를 부르게 했다. 대상 설정은 데이터(경로 매핑, 손 처리 규칙)로 바꿔서 패널에서 고칠 수 있게 했다.

## Considered Options

- **bash `deploy.sh`를 유지하고 워커가 실행한다**: 지금 돌아가는 엔진을 그대로 쓸 수 있다. 하지만 패널이 텍스트 출력을 해석해야 하고, 데이터로 된 대상 설정을 jq로 읽어야 해서 버렸다.
- **엔진을 스킬 폴더에 둔다**: 스킬은 개인 설정 폴더라서 엔진을 시험하거나 버전을 관리하기 어렵고, 패널이 플러그인 밖 경로에 의존하게 된다.

## Consequences

- run 폴더 형식과 확인 코드 규칙은 bash 시절과 같게 둔다. 그래서 bash로 만든 run도 새 엔진이 읽고 되돌릴 수 있다.
