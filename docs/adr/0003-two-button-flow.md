# 패널의 반영은 "반영 목록 만들기"와 "업로드" 두 번만 누른다

처음 패널은 준비 확인, Plan, Backup, Upload, Verify를 각각 눌러야 해서 IntelliJ의 FTP 배포보다 번거로웠다. 사람이 실제로 판단하는 곳은 "이 PR을 반영할까"와 "이 목록을 올릴까" 두 군데뿐이다. 그래서 준비 확인·plan·백업을 **반영 목록 만들기** 하나로, 직전 재대조·업로드·대조를 **업로드** 하나로 묶었다. PR은 목록에서 고르기만 하고, 시작은 버튼으로 한다(누르자마자 시작하면 잘못 누른 것도 바로 돈다). CLI는 `plan --backup` 과 "올린 뒤 이어서 대조하는 upload" 로 같은 묶음을 제공한다.

## Considered Options

- **단계마다 버튼 유지**: 단계별로 확인할 수 있지만, 백업과 대조는 사람이 판단할 것이 없는 읽기 작업이라 누르는 수만 늘었다.
- **백업을 업로드 쪽에 묶기**: 업로드 직전에 백업하면 백업과 업로드 사이 간격이 짧다. 하지만 업로드 직전에 어차피 운영 파일을 다시 대조하므로 얻는 것이 적고, 백업이 실패했을 때 업로드 버튼을 누른 뒤에야 알게 된다.

## Consequences

- 안전장치는 그대로다: 업로드 직전 재대조, 확인 코드, 대상별 잠금, 백업 없이는 업로드 불가.
- 백업은 반영 목록을 만들 때 받는다. 그 뒤 운영 파일이 바뀌면 업로드 직전 재대조에서 멈춘다.
- 백업이나 대조가 따로 실패했을 때만 **백업**, **다시 대조** 버튼이 나온다.
